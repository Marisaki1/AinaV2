# Validation - 0.22.0

12 November 2026. Corrects graph mouse interaction, Markdown/image insertion, linked portraits and whole-project transfer for the existing local Windows installation.

## Delivered behavior

- Affinity guides and shared relationship/family/hierarchy diagrams: non-passive mouse-wheel zoom around the pointer, captured middle-button panning over both background and nodes, and relevant right-click menus. Affinity source/edge menus inspect original notes, focus connections and expose permitted owner actions. Background menus provide zoom/fit. Shared diagrams open originals and offer camera actions. Camera gestures do not change original layout positions. Existing left drag and keyboard arrangement remain available in affinity guides.
- Menus are measured and clamped to the actual viewport, support arrow keys/Home/End/Escape, dismiss on outside interaction, and keep reader dialogs open when only the menu closes. Shift + right-click retains the browser menu. Reader menus omit owner editing/navigation actions. Context interception is scoped to diagrams; normal text inputs keep their browser menus.
- The rich editor has an MD insertion dialog with source, sanitized preview and insertion at the existing selection. Pasting recognized Markdown opens this dialog. It supports the existing Markdown parser's headings, lists, tables, fenced code, links and images. Markdown conversion lifts image nodes out of paragraphs/headings to match the editor schema while retaining surrounding text/marks; list items keep their required leading paragraph. Existing source prose remains intact.
- Parse errors retain the Markdown draft. Escape/navigation cancellation and browser unload guards protect pending insertions. Markdown is converted into the existing rich JSON document; Markdown source files and lossless Markdown roundtripping are not claimed.
- Image insertion accepts direct HTTP/HTTPS URLs and uploaded images. Linked portrait inputs are available in the original editor, affinity inspector and character/location dossier. Cover URLs render in graph portraits, library/dossier/cast cards, party views, notebook cards, session media and reference/desk pins. Published-reader projections derive portrait URLs from published source snapshots rather than draft fields.
- The image URL validator rejects executable/data/file/protocol-relative/credential-bearing/malformed URLs and raw control/space characters. Same-world checks still apply to local media IDs. The browser CSP now permits external HTTP/HTTPS images while keeping scripts and API connections same-origin and frames/objects blocked. The server does not fetch or proxy supplied URLs. Source prose images request no referrer. Notebook HTML retains external image URLs with an image-only remote allowance; those images require network access and a host that permits embedding. Uploaded images remain the offline option.
- **Prepare WorldBuilder Transfer.cmd** creates a ZIP in `transfers` containing source, built app, dependency locks/setup launchers, a verified complete database/uploaded-media backup, checksums, instructions and **Restore transferred data.cmd**. Runtime environments, caches, hidden environment files, raw database files and QA workspace are excluded. On the destination Windows PC: extract, run Setup, restore transferred data into a new folder, then Open WorldBuilder. Restore refuses existing data. Accounts/password hashes, original identities and history survive; browser-only preferences and externally linked image bytes are not included.
